# 嵌入式 C 规范（EMBEDDED_C_STANDARD）

> **一句话**：嵌入式 C 的错，多数不是"写错了"，而是"**在硬件的真实时序/内存/并发模型下**错了"。
>
> 本文件是 **C 代码规范的单一来源**。其他文件只引用，不复制。

---

## 1. 适用范围

全部手写 C 代码（`.c/.h`）与内联汇编。

⚠️ **不适用于**：厂商生成的代码（见第 8 节——那类文件有**另一套规则**）。
⚠️ **不强制统一架构**：裸机事件驱动、前后台、RTOS 各自的写法不同，本规范只定
**共同底线**，不要求所有项目采用同一种架构。

---

## 2. 命名与函数职责

| 项 | 规则 |
|---|---|
| 命名风格 | **跟随所在文件已有风格**（本工程 CubeMX 系用 `HAL_*` / `MX_*`；自写用清晰英文） |
| 函数长度 | 单函数**单一职责**；超过 ~60 行先问"该不该拆"，但不为了拆而拆 |
| 参数 | 指针参数注明方向：`const T*` = 只读；`T*` = 会改 |
| 返回值 | **不要用返回值兼职两个意思**（如 0 既表示"没数据"又表示"出错"）；必要时用 `enum` |

---

## 3. 指针 / 数组边界 / 生命周期

- **每次解引用前问**：这个指针有没有可能为空 / 已失效 / 指向未映射区？
- 数组访问**必须先验证索引**。`idx < N` 是底线，不是可选项。
- **环形缓冲**：容量用**2 的幂** + `& (size-1)`；**满时拒绝写入**（宁可丢新数据，
  也不覆盖尚未处理的数据）—— 见 `skeleton/tests/host/test_ringbuf.c`
- **生命周期**：谁分配谁释放；函数**不得**返回指向栈变量的指针；
  中断里**不得**释放主循环持有的资源。

---

## 4. 整数与错误处理

- **整数溢出**：算长度/偏移/计数时，先想"会不会溢出"。
  `uint16_t` 做 `a*b` 可能截断 → 先转 `uint32_t` 再乘。
- **有符号/无符号混用**：`int` 与 `unsigned` 比较会隐式转换，负数变巨大。编译器警告要当真。
- **错误处理不能吞**：`if (HAL_xxx(...) != HAL_OK) { /* 什么都不做 */ }` 是最危险的写法。
  要么返回错误、要么记录、要么进入明确的失败路径。
- **失败路径要有界**：不要"失败了就重试到成功"。

---

## 5. ISR / DMA / 并发 / volatile

| 规则 | 说明 |
|---|---|
| **共享变量必须 `volatile`** | 中断与主循环共享的每个变量都要；漏了会被优化掉读操作 |
| **单写者原则** | 一个变量**只有一个**上下文集写（如 `head` 只在中断写，`tail` 只在主循环写）→ 无需加锁 |
| **ISR 要短** | 中断里只做"收数据 + 置标志"，重活留给主循环 |
| **不要在 ISR 里阻塞** | 不要 `HAL_Delay`、不要等 TC、不要长循环 |
| **DMA 缓冲区** | 必须对齐、必须在内存布局里**显式告知**（MPU/cache 场景），且**生命周期覆盖传输全程** |
| **中断优先级** | 与 RTOS 的 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 配合时，**知道自己在哪一侧** |
| **临界区** | 跨上下文读写多字段时，用关中断/RTOS 临界区——但要**短** |

> **实例对照**：本工程曾因"收 1 字节 → 阻塞等 TC 发 1 字节"导致连续输入丢字节。
> 正确做法是**中断收 + 环形缓冲 + 非阻塞发（只等 TXE）**。
> 详见 `adapters/stm32-keil-ac5/PITFALLS.md`。

---

## 6. 超时 / 阻塞 / 实时性

- **一切等待都要有超时**。裸机用计数器/Tick；RTOS 用带超时的 API。
- 写"等某标志"的循环前，先答：**它可能永远不来吗？** 可能 → 必须有超时和失败处理。
- **实时性声明要诚实**：如果某段代码要求"必须在 X µs 内完成"，
  把它作为注释/测试写出来，而不是留在脑子里。

---

## 7. 内存与资源预算

- 新增缓冲区/表之前，先算**Flash 与 RAM 预算**（本项目有自动检查：
  `tests/test_static.py::test_image_fits_flash_and_ram`）。
- 栈深度：递归、大局部数组、`printf` 族在深调用里都可能吃爆栈。

---

## 8. 🔒 生成代码 / 启动文件 / 链接脚本 / 硬件配置保护

**这一类文件有独立规则，因为它们"看起来能改"，但改了会被覆盖或在重新生成时丢失。**

| 文件类型 | 规则 |
|---|---|
| CubeMX/厂商生成代码（`main.c` 的 `SystemClock_Config`、`hal_conf.h`、`sdio.c`…） | **手改前先想**：下次"重新生成"会不会冲掉？**改完必须回头改配置源**（`.ioc`），并跑一致性检查 |
| 启动文件（`startup_*.s`） | **不是生成物**，是手写源文件；改动前说明原因 |
| 链接脚本 / 分散加载（`.sct`） | 改动会影响内存布局 → 必须同时说明 Flash/RAM 影响 |
| 硬件配置（引脚、时钟、外设参数） | **任何改动都要能在验收标准里对应到一条可观察现象**（如"115200 能解出数据"） |
| `.ioc` 等生成器配置 | 属于"配置源"，与代码**必须一致**（本项目有 `tools/check_ioc.py` 自动检查） |

> **实例对照**：本工程两次被"重新生成冲掉手改修复"咬到
> （时钟 `HSE_VALUE/PLLM`、`sdio.c` 的 `Init.BusWide`）。
> 这类 bug **不影响当前构建**，只在下次生成时发作 —— 是最难查的一类。

**禁止**：未经授权修改 Option Bytes、全片擦除配置、时钟源选择、供电相关配置。

---

## 9. 验收标准（可检查）

- [ ] 新增/修改的共享变量已加 `volatile`，且遵守单写者原则
- [ ] 所有数组访问有边界检查
- [ ] 所有等待都有超时与失败路径
- [ ] 无整数溢出风险（长度/偏移/乘积已审）
- [ ] 未吞掉任何错误返回值
- [ ] 若触及生成代码/启动文件/链接脚本/硬件配置 → **已说明原因与影响**
- [ ] 若改了生成代码 → 配置源已同步，且一致性检查通过
- [ ] 若新增缓冲区 → 内存预算检查通过
