# Python 自动化脚本规范（PYTHON_AUTOMATION_STANDARD）

> **一句话**：自动化脚本的目标不是"能跑"，而是**跑挂的时候能说清为什么挂、挂了之后不留下烂摊子**。
>
> 本文件是 **Python 工具/脚本规范的单一来源**。其他文件只引用，不复制。

---

## 1. 适用范围

`tools/`、`tests/` 下的全部 Python：构建/烧录封装、串口与调试工具、编排脚本、测试。

---

## 2. 退出码语义（必须统一）

| 码 | 含义 | 谁的问题 |
|---|---|---|
| `0` | **PASS** —— 被测对象通过 | — |
| `1` | **FAIL** —— **被测对象**不通过 | 被测的东西 |
| `2` | **ERROR** —— **工具自身**/连接/参数错误 | 工具 |

> **为什么必须分开**：把"被测失败"和"工具坏了"混成一个非零码，
> 会让人误判问题在哪一层。本平台全部工具遵循此约定。

- 必须能被 `pytest` / CI / 上层脚本**稳定判读**
- 不允许"总是返回 0"（等于没有判据）

---

## 3. 命令执行

- **每个子进程调用都必须有 `timeout`**（含模块级探测！否则 pytest 收集阶段就会挂死）
- 用 `subprocess.run([...], capture_output=True, timeout=N, check=False)`，
  **不要** `shell=True` + 字符串拼接（注入与转义风险）
- 明确指定 `cwd`，不要依赖调用者的当前目录
- **编码**：Windows 上子进程 stdout 默认是 **GBK**，而调用方常按 UTF-8 解码 →
  中文乱码 → **字符串比较失败、判断分支走错**。统一给子进程设 `PYTHONIOENCODING=utf-8`
- **环境变量覆盖硬编码路径**：`os.environ.get("AUTOLAB_XXX", <默认值>)`，
  默认值可以写死本机路径，但**必须有出口**

---

## 4. 异常与资源清理

- **资源必须用 `try/finally` 或 `with` 释放**：串口、文件、临时目录、**调试会话**
- **失败时的清理比成功时更重要**：
  - 例：调试工具必须保证"无论中途怎么挂，目标都被恢复运行"
    → `finally: ensure_running()`（本平台 `tools/debug_probe.py` 的硬约束）
- **不要 `except: pass`**。要么处理，要么带上文重新抛出
- **区分异常类型**：`ModuleNotFoundError` 缺的是谁？——
  不要把"适配器缺依赖"和"没装适配器"混为一谈（见 `tools/preflight.py` 的分流）

---

## 5. 日志与结构化输出

- **给人看的**：正常行文 + 明确的 `[ OK ] / [WARN] / [MISS] / [SKIP]` 之类的级别标记
- **给机器看的**：一行 JSON（`json.dumps({...}, ensure_ascii=False)`），键名稳定
- **失败必须带修复建议**：报告"哪里错"之外，尽量给**可直接复制的修复命令**
- **不要静默失败**：什么都不打印然后返回非零 = 最坏的体验

---

## 6. 测试隔离

- 测试**不得污染仓库**：产物写到临时目录或**已 gitignore** 的目录（`runs/`、`build_logs/`）
- 用 `tempfile.TemporaryDirectory()`，不要手写固定名字的临时文件
- 测试之间**不共享可变状态**；顺序无关
- 硬件用例必须有 **timeout / 有限重试**，且**标记分层**（`hardware` / `nohardware`）

---

## 7. 配置与依赖

- 依赖**锁定版本**（`requirements.txt`），换机器可复现
  - ⚠️ `requirements.txt` 里写非 ASCII（中文注释）会让 `pip install -r` **直接崩**
    （pip 按本地编码解码该文件）→ 必须在首行加 `# -*- coding: utf-8 -*-`
- 所有"本机相关"的东西（端口、工具链路径、用户名）走**环境变量 + 默认值**
- 新增依赖前先问："能不能不加？"

---

## 8. 测试证据与失败报告

失败时必须留下**足以复现**的东西：

| 必留 | 说明 |
|---|---|
| 固件/产物的**指纹**（如 `.axf` 的 SHA256） | 知道当时烧的是哪一版 |
| 代码版本（git HEAD + **是否有未提交改动**） | 脏工作树的产物无法从任何 commit 复现 → 连 diff 指纹一起留 |
| 原始观测（原始字节 / 寄存器 / 日志） | 不做二次加工，保留最原始的 |
| 判定结论 + **它不能证明什么** | 避免把 PASS 当成"功能完全正确" |

**证据三原则**：可复现、可追溯、**不美化**（失败就是失败，未跑就是未跑）。

---

## 9. 验收标准（可检查）

- [ ] 退出码符合 `0/1/2` 约定，且**判据双向标定过**（见过它红）
- [ ] 每个 `subprocess` 调用都有 `timeout`
- [ ] 子进程设了 `PYTHONIOENCODING=utf-8`
- [ ] 硬编码路径都有环境变量出口
- [ ] 资源用 `finally`/`with` 释放；调试类工具保证**恢复设备状态**
- [ ] 失败路径输出**可复制的修复建议**，不是裸 traceback
- [ ] 失败时留下了指纹 + 代码版本 + 原始观测
- [ ] 测试产物写入临时目录或已忽略目录，`git status` 保持干净
