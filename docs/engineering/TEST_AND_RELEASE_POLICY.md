# 测试与放行策略（TEST_AND_RELEASE_POLICY）

> **一句话**：**NOT RUN ≠ PASS**。没跑过的，永远不能说"通过"。
>
> 本文件是 **测试门禁与放行规则的单一来源**。其他文件只引用，不复制。

---

## 1. 分层门禁（按代价从低到高，能过就别往下走）

| 层 | 内容 | 需要硬件 | 典型耗时 | 命令（示例） |
|---|---|---|---|---|
| **L0 静态** | 语法/结构检查、环境自检、忽略规则 | ❌ | < 1 s | `python tools/preflight.py` |
| **L1 构建** | 编译 + 产物契约（符号/预算/向量表） | ❌ | ~20 s | `python tools/build.py` |
| **L2 单元** | 宿主机单元测试（跑**固件里的真实代码**）+ 无板用例 | ❌ | < 1 s | `pytest -m "not hardware"` |
| **L3 HIL** | 烧录 + 真机用例 + 失败取证 | ✅ | ~1 min | `python tools/hil.py` |

**规则**：
- **L0–L2 是每次改动的最低要求**；L3 在"改动影响硬件行为"时必做。
- **下层红 → 不看上层**（L1 挂了，L2/L3 的结论毫无意义）。
- 跨层复用已有工具，**不要为出报告重写判据**。

---

## 2. 证据规则：PASS / FAIL / NOT RUN

| 状态 | 含义 | 允许出现在 |
|---|---|---|
| **PASS** | **实际执行过**，且判据全部满足 | 报告结论、提交说明 |
| **FAIL** | 实际执行过，判据不满足（**要带原始输出**） | 报告结论 |
| **NOT RUN** | **没执行**（缺环境/缺硬件/未授权） | 报告里必须**显式列出** |

**硬性要求**：

- **未执行的，一律标 NOT RUN**，不许写成"应该没问题""代码上看是对的"
- **静态阅读代码 ≠ 测试**。可以说"从代码上看"，但**不能算 PASS**
- 报告里必须同时给出：**已验证 / 未验证 / 已知限制**
- 判据必须**双向标定过**：亲手制造一次失败，看它**准确报错**，这条判据才算数

## 3. 提交前审查清单

```
[ ] git status —— 变更文件与计划一致，无计划外改动
[ ] git diff   —— 每处改动都能对应到任务要求
[ ] L0 通过    —— preflight / 静态检查
[ ] L1 通过    —— 构建四判据（退出码 / 0 错 0 警 / 编译动作数 / 产物时间戳）
[ ] L2 通过    —— pytest -m "not hardware"
[ ] L3         —— 影响硬件行为时执行；否则显式标注 NOT RUN（缺硬件）
[ ] 证据       —— 失败时留了指纹/版本/原始观测
[ ] 回滚方案   —— 能说清怎么干净退回
[ ] 提交范围   —— 只含本次任务的改动，不含用户的其它未提交内容
```

## 4. 🔒 硬件操作的人工授权边界

**Agent 不得自行发起**下列动作，必须先说明"要做什么、影响什么"并获**明确授权**：

| 动作 | 说明 |
|---|---|
| 烧录 / 下载固件 | 会改变板子上的程序 |
| 全片擦除 / Option Bytes / 时钟源 / 供电配置 | 可能让板子起不来 |
| 复位 / 运行控制（含调试器 halt） | 会打断正在进行的实验 |
| 连接/占用串口与调试器 | 会与用户的会话冲突 |
| 任何针对**生产设备 / 客户设备**的操作 | 一律禁止 |

**调试类操作的额外硬约束**：会话结束**必须把目标恢复运行** ——
停在 halt 会让下一个人误判"固件挂了"（本平台在 `tools/debug_probe.py` 用
`finally` 强制保证）。

**允许无需授权**：只读探测（列端口、列探针、读寄存器/内存、读环境）。

## 5. 自动化门禁的原则

- Hooks / CI **只做确定性的、适合自动化的检查**（格式、语法、构建、既有测试）
- **复杂的架构判断、代码审查、测试方案选择** → 由 Skill/人 来做，不塞进 hook
- **任何会阻塞的门禁必须给出：失败原因 + 修复提示**
- 🚫 **绝对不能为了让门禁通过而**：删测试、放宽断言、吞异常、跳过检查、
  改 `.gitignore` 藏文件。**这类操作本身就是最严重的违规。**

## 6. 验收标准（可检查）

- [ ] 报告区分了 **已验证 / 未验证 / 已知限制**
- [ ] 所有"未执行"的项都标了 NOT RUN
- [ ] 每条通过的判据都**双向标定过**
- [ ] L0–L2 在改动后重跑过
- [ ] 影响硬件行为的改动做了 L3（或显式标注未做及原因）
- [ ] 硬件操作经过授权；调试会话结束设备已恢复
- [ ] 没有任何"为了过门禁"的放水操作
